# MemeVerdict v2 project review — 2026-09-05

## Scope and status

MemeVerdict is a full dApp MVP: React/Vite frontend, MetaMask integration,
Python Intelligent Contract, and deployment evidence. This review preserves
both copies of the deployed v2 contract without edits or redeployment.

The successful historical deployment is useful evidence, but is not a security
audit or proof that every event category and adversarial source works safely.

## Frontend corrections

- Use the installed SDK's `waitForTransactionReceipt` with FINALIZED instead
  of nonexistent `waitForDecision` / `waitForFinalization` methods.
- Inspect execution success separately from finalization.
- Apply configured RPC and chain information to both read and signing clients.
- Reject malformed claim responses rather than manufacturing empty OPEN claims.
- Keep RPC failure distinct from an empty explorer; clear stale detail state.
- Match trimmed field lengths and the 20-character token-symbol limit.
- Guide users to full HTTP(S) source URLs: the v2 fetch loop ignores bare domains.
- Keep wallet event subscriptions active after a local disconnect/reconnect.
- Do not turn script/data URLs stored in evidence into executable links.
- Commit the npm lockfile for reproducible dependency installation.

## Material limitations in the deployed v2 contract

1. **Source trust boundary:** `_accepts` checks `s_str in dom`, not hostname
   equality or a dot-boundary subdomain. `official.example.attacker.example`
   can match an allowlist entry of `official.example`. The validator uses OR,
   so only one of leader/validator top URLs needs to pass. The LLM's top URL
   is not checked against the actual fetched URL set. Caller-designated sources
   are not independently certified as authoritative.
2. **Evidence commitment:** SHA-256 commits to a composed blob of rendered,
   truncated source text, not authenticated HTTP response bytes. The full blob
   is not archived on-chain; exact digest reconstruction after page changes is
   not guaranteed. Validators compare verdict/source-domain conditions, not
   equality of the evidence digest.
3. **Evidence and prompt controls:** Only the first six unique URLs are fetched,
   each truncated to 6,000 characters. Optional evidence can be appended by any
   caller. There are no overall evidence-list bounds and no robust separation
   that guarantees resistance to instructions embedded in fetched content.
4. **Lifecycle:** Deadline is interpreted by the prompt, not an on-chain time
   gate. UNRESOLVED is terminal for that claim. `created_at` / `resolved_at`
   are deterministic counters, not timestamps. The owner can pause new work.
5. **Testing:** The repository's direct-mode suite was not executed in this
   runtime because pytest/GenLayer testing dependencies were unavailable.
   The documented `tests/integration` directory does not exist. Historical
   full-consensus evidence and live read checks are separate from unit tests.

## Assessment and next milestone

This is a demonstrable full project, but it should not be described as having
hardened evidence authentication equivalent to a completed trust-boundary
upgrade. Acceptance remains a reviewer decision. A future explicitly approved
v3 should require exact parsed host checks on BOTH parties, verify cited URLs
were fetched, bound inputs, preserve reproducible evidence, and test hostile
sources plus YES/NO/UNRESOLVED outcomes with real consensus. That requires a
new contract and fresh evidence; the frontend alone cannot repair deployed logic.
